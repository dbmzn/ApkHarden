# 常见问题

[返回 README](../README.md)

## 需要安装 Android SDK 吗？

查看 APK、生成码图、签名和加固使用 JVM 库及仓库中的预编译壳资源，普通桌面构建无需 Android SDK / NDK。

设备功能需要 ADB，可使用 Android SDK 的 Platform-Tools。只有重建壳资源、生成真机验证测试包时才需要额外的 SDK、Build-Tools 或 NDK。具体要求见[开发验证说明](development.md)。

## 编译时找不到 JDK 17

项目在 `build.gradle.kts` 中配置了 `jvmToolchain(17)`，先确保已安装 JDK 17，再检查：

```sh
java -version
./gradlew --version
```

macOS 可列出已安装 JDK：

```sh
/usr/libexec/java_home -V
```

若本机已有 JDK 17，可设置 `JAVA_HOME` 后重新启动 Gradle；IDE 的 Gradle JVM 也应配置为可用的完整 JDK。打包还需要该 JDK 提供 `jpackage` 和 `jlink`。

## 首次启动或打包为什么要下载 scrcpy？

macOS / Windows 的应用资源准备任务会下载对应平台的 scrcpy 3.3.4，并校验 SHA-256。下载用于镜像和兼容录屏，失败时先查看 Gradle 日志中的网络或校验错误。

可以单独执行以下任务，区分资源下载问题与源码编译问题：

```sh
./gradlew prepareScrcpyResources
./gradlew compileKotlin
```

下载缓存位于 Gradle 用户目录的 `caches/apkharden/`；应用资源位于项目的 `build/app-resources/`。不要通过跳过校验使用来源不明的二进制文件。

## 应用提示找不到 ADB，或没有设备

先在终端执行：

```sh
adb version
adb devices -l
```

- **找不到命令**：确认已安装 Platform-Tools，并配置 `ANDROID_HOME` / `ANDROID_SDK_ROOT` 或 `PATH`。应用也会检查 macOS、Windows 和 Linux 的常见 SDK 位置。
- **列表为空**：检查数据线、USB 调试和连接方式，解锁手机后重试。
- **unauthorized**：在手机上确认 USB 调试授权，再刷新设备。
- **offline**：重新连接设备，确认终端 ADB 已能正常通信后再回到应用。

打包资源中附带的 adb 不会自动加入系统 PATH；当前设备服务仍按 SDK、常见目录和 PATH 查找 ADB。

## 无线配对成功，但没有连接上

配对与日常调试可能使用不同端口。配对码弹窗内的端口用于配对，无线调试首页显示的地址用于连接。不要把配对端口直接当作后续连接端口。

同时确认电脑与手机的网络可互通。二维码过期可刷新；网络不支持设备发现时，可尝试配对码或手动地址。旧版 TCP 调试需要先通过 USB 开启，完成后建议使用工具关闭旧版无线调试。

## 镜像找不到 scrcpy，或录屏失败

macOS / Windows 运行与打包流程会准备 scrcpy；Linux 需要自行安装。应用优先查找显式指定路径、应用资源、工作目录和 PATH。

macOS 开发运行可指定：

```sh
APK_HARDEN_SCRCPY="$PWD/build/app-resources/macos/scrcpy/scrcpy" ./gradlew run
```

录屏按设备原生 `screenrecord`、scrcpy、连续截图编码的顺序尝试兼容路径。最后一种是低帧率保底方案，画面流畅度与前两种不同。系统录屏限制、设备编码器或连接异常仍可能导致失败，请结合页面输出排查。

## 为什么切换页面后镜像或文件传输结束了？

截图、镜像、手机剪贴板、文件互传和「更多调试」共用设备会话。在这些工具之间切换会保留设备选择和镜像连接；切换到二维码、设备验证、APK 工具等其他页面时会释放该会话。

文件互传在离开页面时取消当前传输。临时记录按设备隔离，离开设备会话或关闭应用后清除，不是长期文件历史。

## 手机剪贴板没有内容，或还是上一次的文字

先在手机上复制一段测试文字。此功能仅接收文字和链接，部分 Android 版本或厂商系统会限制剪贴板读取。

页面不会保存历史；但手机清空剪贴板或系统不返回新内容时，已显示的旧文字可能保留至离开页面。可以尝试「重新连接」，不要把旧文字视为手机当前剪贴板的实时确认。

## 文件保存在哪里？为什么不能覆盖同名文件？

截图、录屏和诊断 ZIP 自动保存到当前用户的 `Downloads`，文件名带时间戳。二维码保存时由系统文件对话框选择路径；加固输出由输入框指定。

文件互传主动拒绝覆盖同名目标文件。更换文件名或选择其他目录后重试。手机目录也受 Android 文件权限限制，不是所有路径都可读取或写入。

## 为什么不能使用 APK 加固？

常见原因包括：签名配置未保存、输入与输出为同一文件、输入 minSdk 低于 23、Split APK、debuggable / testOnly、输入签名与所选 keystore 不一致、多签名者或签名轮换链。

已经有效签名的 APK 应使用原发布 keystore。不要为了通过检查随意换证书。完整准入条件见[加固说明](hardening.md#输入条件)。

## 签名密码如何保存？换肤会影响签名吗？

macOS 使用 AES-GCM 加密密码，加密密钥存于当前用户的钥匙串；Windows 使用当前用户的 DPAPI 保护密码。Linux 目前不支持安全保存这份配置。

外观与签名配置位于不同的 Preferences 节点，恢复默认皮肤不会清除签名资料。外观选择会自动保存，换肤窗口若提示保存失败，可点击「重试保存」。

## 默认皮肤是什么？为什么重启后还是其他颜色？

首次启动默认为「经典绿青 + 浅色」。手动选择其他皮肤或外观模式后会记住选择。

点击左下角「换肤 → 恢复默认」可回到经典绿青与浅色模式。「跟随系统」控制深浅外观，不会自动更换皮肤。

## 支持拖入 APK、导出 Manifest 或自定义皮肤吗？

当前文件入口使用「浏览」或输入路径；Manifest 页面提供查看、搜索与风险提示，没有独立的报告导出按钮。皮肤库内置 4 套配色，目前没有任意颜色编辑器。

功能以实际界面为准，不应将参考项目的功能直接视为 ApkHarden 已实现。

## 16 KB ZIP 对齐是否等于完整支持 Android 16 KB 页面？

不是。ZIP 中未压缩 SO 的文件偏移对齐，与 SO 自身的 ELF 段对齐及运行时兼容性是不同层面的要求。工具处理重打包对齐，并提供预编译壳库；原有业务 SO 仍需自身满足目标设备要求。

应在目标 Android 版本、ABI 和页面大小环境中验证安装、启动及业务流程。详见[能力边界](hardening.md#能力边界)。

## 普通测试通过，是否就能发布？

常规测试不会自动完成所有真机、ROM 或业务流程验证。需要设备或钥匙串的测试通过环境变量显式开启；历史验证报告也只对当时的版本和环境负责。

见[开发验证说明](development.md)和[macOS 验证记录](macos-verification-2026-09-05.md)。

## 通用工具的输入会上传或保存吗？

JSON、文本对比、编码与时间计算均在本机进行，不会自动读取剪贴板，也不持久保存输入历史。工作内容只在当前应用会话中保留，关闭应用后清除；只有点击「保存文件」才会导出结果。

JWT 解析只展示内容和 exp，不证明签名有效。Cron 预览不会创建定时任务。更多说明见[通用工具使用说明](developer-tools.md)。

## 图片压缩和 TinyPNG 一样吗？会覆盖原图吗？

图片工具使用本机 pngquant、OxiPNG 与 MozJPEG，不调用 TinyPNG API。智能模式允许像素变化，无损模式只优化编码；体积收益取决于素材，当前没有与 TinyPNG 做同图对照。所有模式保留尺寸和格式，较大的结果自动回退原文件。

添加图片时建立本机会话快照，压缩后需另存。原图和已有输出均不覆盖，重名自动编号。当前支持静态 PNG / JPEG；macOS 已内置引擎，Windows / Linux 需自行配置。更多细节见[图片压缩说明](image-tools.md)。
